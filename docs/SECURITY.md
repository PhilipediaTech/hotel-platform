# Security pass (T-102)

PRD NFR "Security": OWASP ASVS level 2 as the target; MFA for privileged roles; dependency
scanning in CI; secrets only in environment variables. Test plan (tab 8): the tenancy suite,
and "dependency audit shows no high or critical issues without a waiver" before a release.

Reviewed against **OWASP ASVS 5.0, level 2**, chapter by chapter, on 2026-11-07 (main at
f1b8606 plus this branch). ✔ met, ◐ partly (gap named), ✖ open, — not applicable.

## What guards every route

| Guard                      | Where                                                      | Proven by                                                                                                                  |
| -------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Signed in (401)            | `mountRoute` → `requireAuth`, before anything else         | `access.int.test.ts`: every non-public route, no session → 401                                                             |
| Same-origin writes (CSRF)  | middleware step 6, `core/csrf.ts`                          | every state-changing route, missing or foreign `Origin` → 403                                                              |
| Property membership (404)  | middleware step 7, `core/tenancy.ts`                       | tenancy suite: every property-scoped route, another tenant's record or property → 404                                      |
| Permission (403)           | `mountRoute`, **now before body validation** (this ticket) | every route with a permission, member without it → 403, whatever they send                                                 |
| Support sessions read-only | `core/tenancy.ts`                                          | every property write under a support session → 403                                                                         |
| Platform staff only        | platform router guard                                      | every platform route, hotel staff → 403; all live under `/platform/`                                                       |
| Reviewed exceptions        | `access.int.test.ts`                                       | the public routes (15), pre-MFA routes (4) and member-wide routes (23) are frozen lists; a new one fails CI until reviewed |

## Changes in this ticket

- **Permission before validation.** `mountRoute` now checks permission (and module, then
  export) before reading params, query and body. Someone without the permission used to get the
  route's validation messages first, which describe its fields. Now they get 403. Headers are
  still checked first, since `X-Property-Id` is needed to know the property.
- **Route-wide sweeps** (`apps/api/src/core/access.int.test.ts`) over every route in
  `API_ROUTES`, plus the reviewed lists above. A new route is checked without anyone
  writing a test for it.
- **CI:** a second audit step, so runtime packages stay at zero known issues.
